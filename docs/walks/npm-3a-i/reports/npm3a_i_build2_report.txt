ONE THING TO KNOW FIRST: AN UNINTENDED NETWORK CALL TO EXPO
While I was building the Step 3 header test, my first version of the test harness let the REAL expo-server-sdk reach Expo's servers.
  - Why: fakeEnv loaded the real SDK, through jest.requireActual, before the node-fetch stand-in was registered.
  - What was sent: 4 HTTP POSTs to Expo's push API (https://exp.host/--/api/v2/push/send). That was 3 in one failing test run and 1 in a debug run.
  - What they carried: the obviously fake bearer token "fake-expo-access-token-for-tests-only" and a fake recipient token "ExponentPushToken[recipient-R-token]".
  - Result: Expo rejected all of them with AUTHENTICATION_ERROR. Nothing could be delivered and nothing was written to Firebase. No real secret was involved.
  The fix is in commit a7a8ec9:
  - The harness now replaces node-fetch in EVERY suite, with a stand-in that throws unless a test supplies its own.
  - Real-SDK mode refuses to start without a stand-in.
  - The harness no longer loads the real SDK for token checks.
  - Two tests pin these guards.
